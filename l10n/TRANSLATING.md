# Translating Blender Local

The app shows its UI in the language chosen in Preferences ▸ Interface ▸
Language (Automatic follows the iPad). Each language's table,
`Resources/Localization/<lang>.lproj/Localizable.strings`, is generated by
`scripts/l10n/build.py` from two sources:

1. `l10n/<lang>.json`: the app's own translations, one JSON object
   `{"English": "translation"}`. These win.
2. Blender's official catalog for that language, from the bpy the app ships,
   so a Blender term reads as it does in Blender in that language.

`scripts/l10n/extract.py` collects every UI string in `Sources/` into
`l10n/keys.json`; `build.py` lists what neither source translates in
`l10n/missing/<lang>.json`. After adding UI text: run both scripts, translate
the new entries of `missing/<lang>.json` into `<lang>.json`, run `build.py`.

## Rules for translations

- Translate everything a user can see: menu items, buttons, labels, tips, help,
  errors, status messages.
- Leave out strings that are not user-facing: code, Python, identifiers, file
  formats ("PNG", "MP4"), proper names alone.
- Keep proper names as they are inside sentences: Blender, Blender Local,
  Cycles, EEVEE, Workbench, Metal, iPad, iPadOS, GitHub, Gmail, TripoSG,
  Depth Anything, glTF, USD, FBX, OBJ, Alembic, Python, Monaco.
- `%@` is a value filled in at run time. Keep exactly as many. To reorder, use
  `%1$@`, `%2$@`, numbered by their order in the English string.
- Keep keyboard shortcuts and key names exactly (Ctrl+E, Shift+B, Tab, G, R R,
  F12, (N), Page Up), "…" endings, trailing ":" and spaces, and symbols such as
  × ° % · → ▸.
- Use Blender's own wording for every Blender term (the glossary is the
  generated `Localizable.strings`); concise UI style like Blender's translated
  UI; natural full sentences for longer help and error text.
- A Blender term the app uses in another sense than Blender's catalog chose
  (a menu named "Add" rendered as arithmetic "sum") gets a corrected entry in
  `<lang>.json`, which overrides the catalog.
